## 1. Resumen de Implementación por Bloques

### Bloque A — Núcleo transversal
1. **Jerarquía unificada de errores de dominio (`app/core/errors.py`):**
   - Clase base `DomainError(message, code, status_code)` y subclases:
     - `NotFoundError` (404, `NOT_FOUND`)
     - `ForbiddenError` (403, `FORBIDDEN`)
     - `ConflictError` (409, `CONFLICT`)
     - `ValidationError` (400, `VALIDATION_ERROR`)
     - `ExternalServiceError` (502, `EXTERNAL_SERVICE_ERROR`)
     - `RateLimitedError` (429, `RATE_LIMITED`)
   - Manejador global en `app/main.py`: transforma todas las excepciones de dominio al payload canónico `{success: false, message: str, code: str}`.
   - Manejador 500 genérico y middleware `request_id_middleware`: intercepta excepciones no controladas, las registra con `request_id` (`X-Request-ID`) y responde `{success: false, message: "Internal server error", code: "INTERNAL_SERVER_ERROR"}` sin filtrar trazas internas ni credenciales.
2. **Eliminación de fugas de error (`str(e)`):**
   - Se sustituyeron todas las ocurrencias de `detail=str(e)` y `message=str(e)` por excepciones de dominio tipadas o mensajes de error seguros para el cliente.
3. **Deprecación de `datetime.utcnow()`:**
   - Se migraron todas las ocurrencias en backend, repositorios, servicios y schemas a `datetime.now(timezone.utc)`.
4. **Políticas de autorización desacopladas (`app/core/authz.py`):**
   - Políticas puras sin dependencia de FastAPI: `can_access_project(user, project, team)` y `can_access_diagram(user, diagram, team, project)`.
   - Cobertura completa de membresía: miembros de equipo, Scrum Masters, dueños y administradores.
   - Dependencias FastAPI: `require_project_member` y `require_diagram_access`.
   - `ProjectService` y `DiagramService` delegan directamente a estas políticas eliminando duplicaciones.

### Bloque B — Defectos verificados
| ID | Defecto Original | Solución Implementada |
|---|---|---|
| **B2** | `/auth/logout` no revocaba sesión en servidor | Inclusión de claim `sid` (session ID) en access tokens. `/auth/logout` marca la sesión como inactiva (`is_active: false`). Peticiones subsiguientes con dicho token reciben `401 Unauthorized`. Mantiene compatibilidad hacia atrás con tokens legacy sin `sid`. |
| **B3** | `ai_chat` sin control de pertenencia a proyecto | Aplicación de `Depends(require_project_member)` en todas las rutas de `/api/v1/ai-chat/projects/{project_id}/*`. Verificación de pertenencia estricta en ejecución de tareas (`execute_task`). Usuarios no miembros reciben `403 Forbidden`. |
| **B4** | Campo inexistente `username` en colección `users` | Se corrigió en `ai_chat/router.py`, `context_builder.py` (proyección de `name` y formato de miembros) y `diagrams/service.py` (nombres de participantes no caen a "Usuario"). |
| **B5** | Creación de diagramas sin `project_id` asignaba proyectos ajenos | Si se omite `project_id`, se asocia automáticamente a un proyecto personal perteneciente al usuario autenticado (creándolo si no existe). Si se especifica `project_id`, se valida autorización de acceso (`403` si es ajeno). |
| **B7** | `POST /diagrams/{id}/ai-prompt` construía `SaveGraph` no guardado y notificaba falsamente | Se eliminó el código muerto y la notificación engañosa. Devuelve la propuesta generada sin disparar eventos de guardado hasta que el usuario confirme. |
| **B9** | Cuerpos no tipados / sin límites en `/from-image` y `/ai-prompt` | DTOs Pydantic estrictos (`DiagramFromImageRequest`, `DiagramAiPromptRequest`): decodificación y límite de tamaño de imagen (≤ 8 MB), whitelist MIME (`image/png`, `image/jpeg`, `image/webp`), y prompt con máximo de 4.000 caracteres. |
| **B10** | `InvalidId` de BSON causaba errores 500 en repositorios | Validación en frontera con `validate_object_id` en rutas de `projects`, `diagrams`, `teams`, `folders` y `codegen`, respondiendo `400 Bad Request` con código `INVALID_OBJECT_ID`. |

### Bloque C — Colaboración WebSocket (`collaboration/`)
1. **Protección de Locks con `OP_REJECTED`:**
   - En operaciones de nodos y aristas (`NODE_OPERATION`, `EDGE_OPERATION`), si el elemento está bloqueado por otro usuario, el backend responde inmediatamente `{"type": "OP_REJECTED", "element_id": id, "reason": "locked"}` y no persiste ni retransmite el cambio.
2. **Persistencia atómica sin Read-Modify-Write:**
   - `update_diagram_graph_data`:
     - Adición (`add`): `$push` atómico evitando duplicados.
     - Eliminación (`delete`): `$pull` atómico en nodos y aristas huérfanas conectadas (`source` / `target`).
     - Modificación / Movimiento (`move`, `update`): `$set` con `arrayFilters` (y fallback posicional atómico) actualizando posición y timestamp `updated_at`.
   - Test de concurrencia verificado: ráfaga concurrente de 50 movimientos simultáneos (`asyncio.gather`) sin pérdida de datos.
3. **Límites por Conexión:**
   - Tamaño máximo de mensaje: 64 KB (`MAX_MESSAGE_BYTES = 65536`).
   - Tasa máxima de mensajes: 60 msg/s (`MAX_BURST_PER_SECOND = 60`).
   - Cierre con código WebSocket `4008 (Policy Violation)` si se superan los límites.
4. **Token WebSocket de un solo uso:**
   - `verify_ws_token` consume el token mediante `find_one_and_delete`. Tokens reutilizados son rechazados con código `4001`.
5. **Documentación del protocolo:**
   - Especificación completa de eventos, payloads y códigos de cierre en [`docs/ws-protocol.md`](file:///c:/Users/Ale/Documents/SW1%202-2026/segundo%20examen%20parcial/docs/ws-protocol.md).

### Bloque D — Configuración y Despliegue
1. **Validación de entorno (`Settings.ENVIRONMENT`):**
   - En `production`, el arranque falla de inmediato si `SECRET_KEY` es el valor por defecto o está vacío, o si `CORS_ORIGINS` no contiene al menos un origen válido.
2. **CORS estricto en producción:**
   - En producción solo se permiten los orígenes explícitos listados en `CORS_ORIGINS`. El regex permissive de dominios `*.pages.dev` y `*.trycloudflare.com` queda restringido exclusivamente a desarrollo.
3. **Rate Limiting seguro ante Proxies:**
   - Función de clave de rate limiting que prioriza el usuario autenticado (ID extraído del token) y, en clientes anónimos, analiza cabeceras de proxy confiables (`CF-Connecting-IP`, `X-Forwarded-For`, `X-Real-IP`).
   - Límites añadidos a rutas sensibles:
     - `/auth/register`: 5/minuto
     - `/auth/login`: 10/minuto
     - `/ai/generate`: 15/minuto
     - `/ai/generate-from-image`: 10/minuto
     - `/ai-chat/projects/{id}/messages`: 30/minuto
     - `/codegen/{id}/preview`, `/download`, `/frontend-prompt`: 20/minuto
4. **Contenedorización robusta (`Dockerfile`):**
   - Eliminación del BOM inicial UTF-8.
   - Ejecución bajo usuario no privilegiado `appuser`.
   - `HEALTHCHECK` configurado contra `/health`.
   - Comando de arranque explícito: `uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1 --proxy-headers --forwarded-allow-ips *`.
   - `.dockerignore` exhaustivo para optimizar el contexto de build.
5. **Índices de Base de Datos (`app/core/database.py`):**
   - `users.email` (único)
   - `sessions.refresh_token_hash` (único)
   - `sessions.expires_at` (TTL automático)
   - `diagrams.(project_id, is_deleted)`
   - `diagrams.member_ids`
   - `projects.team_id`
   - `projects.owner_id`
6. **Encabezados de paginación:**
   - `GET /api/v1/users/` y `GET /api/v1/diagrams/` devuelven el encabezado `X-Total-Count` indicando el número total de registros disponibles.

## 2. Cambios de Comportamiento para Frontend y Móvil

> [!IMPORTANT]
> Los equipos de desarrollo de cliente (Web Angular y Móvil Flutter) deben tener en cuenta las siguientes modificaciones de contrato y comportamiento:

1. **Formato Canónico de Errores HTTP:**
   - Todas las respuestas de error (`4xx` y `5xx`) ahora devuelven la estructura estándar:
     ```json
     {
       "success": false,
       "message": "Descripción legible del error",
       "code": "CODIGO_ERROR_ENUM"
     }
     ```
   - Códigos habituales: `NOT_FOUND`, `FORBIDDEN`, `CONFLICT`, `VALIDATION_ERROR`, `RATE_LIMITED`, `EXTERNAL_SERVICE_ERROR`, `INVALID_OBJECT_ID`, `UNAUTHORIZED`.
   - Encabezado `X-Request-ID` presente en todas las respuestas para trazabilidad.

2. **Revocación de Sesión y Logout:**
   - Tras llamar a `POST /api/v1/auth/logout`, el `access_token` actual queda inmediatamente invalidado. La aplicación cliente debe purgar tokens locales y redirigir al login. Intentar llamadas posteriores causará `401 Unauthorized`.

3. **Reconexión WebSocket y Token de un solo uso:**
   - El token devuelto por `GET /api/v1/diagrams/{id}/ws-token` es de **un solo uso**. Si la conexión se pierde, el cliente debe solicitar un nuevo token antes de invocar `ws://.../ws/diagrams/{id}?token={nuevo_token}`. (El servicio frontend ya sigue este flujo).

4. **Nuevo Mensaje WebSocket `OP_REJECTED`:**
   - Si un usuario intenta mover o editar un nodo bloqueado por otro miembro del equipo, el WebSocket devolverá:
     ```json
     {
       "type": "OP_REJECTED",
       "element_id": "nodo_o_arista_id",
       "reason": "locked"
     }
     ```
   - El cliente debe revertir la posición o estado del elemento en el canvas local.

5. **Códigos de Desconexión WebSocket:**
   - `4001`: Token inválido o expirado.
   - `4003`: Acceso no autorizado al diagrama.
   - `4008`: Violación de política (mensaje > 64 KB o ráfaga superior a 60 msg/s).

6. **Paginación y Encabezado `X-Total-Count`:**
   - Al consultar listas (`/api/v1/users/` y `/api/v1/diagrams/`), el conteo total de elementos se obtiene leyendo la cabecera HTTP `X-Total-Count` (exponiendo este header vía CORS).
