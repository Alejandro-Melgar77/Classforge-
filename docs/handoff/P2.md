# Handoff P2 — Un solo cliente LLM (puerto + adaptadores) para Gemini 3.8 Flash

**Fecha:** 31 de octubre de 2026  
**Objetivo alcanzado:** Reemplazo integral de los 5 clientes Gemini duplicados por la capa modular `app/llm/`, segura, desacoplada mediante el patrón de puertos y adaptadores (Hexagonal Architecture), con cero transmisiones de credenciales en URL, validación de modelos, soporte BYOK por cabecera, cortacircuitos (circuit breaker), backoff con jitter, telemetría de tokens (`usageMetadata`) hacia MongoDB `ai_usage`, y suite de pruebas 100% offline. 68 tests (`pytest`) en verde.

---

## 1. Arquitectura de la Capa `app/llm/`

```
app/llm/
├── __init__.py      # Exportación unificada de modelos, puertos, proveedores y registro
├── models.py        # DTOs: LlmMessage, LlmRequest, LlmResponse, LlmUsage
├── ports.py         # Protocolo LlmProvider: generate(req) -> LlmResponse ; stream(req) -> AsyncIterator[str]
├── errors.py        # Jerarquía: LlmError, LlmUnavailable, LlmRateLimited, LlmBadResponse, LlmQuotaExceeded
├── gemini.py        # GeminiProvider: adaptador HTTP v1beta, SecretStr, circuit breaker, retry, repair
├── fake.py          # FakeLlmProvider: adaptador para pruebas unitarias y E2E sin red ni credenciales
├── registry.py      # get_provider(purpose) según Settings.LLM_PROVIDER ("gemini" | "fake")
└── usage.py         # Telemetría asíncrona no bloqueante en colección 'ai_usage'
```

### 1.1 Modelos de Datos (`models.py`)
- **`LlmMessage`**: Turno conversacional explícito con rol tipado (`Literal["user", "model"]`), texto, y soporte multimodal opcional (`image_bytes`, `mime_type`).
- **`LlmUsage`**: Telemetría de tokens extraída del proveedor (`prompt_tokens`, `candidates_tokens`, `total_tokens`, `thoughts_tokens`).
- **`LlmResponse`**: Objeto inmutable con texto generado, `raw_json` estructurado (cuando se solicita esquema), `model` final que respondió, métricas de tokens (`usage`) y `latency_ms`.
- **`LlmRequest`**: Objeto central con:
  - `system: str` (instrucción de sistema desacoplada de los turnos).
  - `messages: List[LlmMessage]` (turnos alternados reales, no bloques concatenados).
  - `temperature: Optional[float]`.
  - `max_output_tokens: Optional[int]`.
  - `json_schema: Optional[Dict[str, Any]]` (esquema JSON estructurado).
  - `thinking: Optional[Literal["low", "medium", "high"]]` (control de profundidad de razonamiento en Gemini 3.8 Flash).
  - `purpose: str` ("chat", "task", "codegen", "vision").
  - `project_id` y `user_id` (para atribución y control de cuotas en P5).
  - `api_key: Optional[SecretStr]` (clave opcional por petición, excluida de logs y reprs).
  - `model: Optional[str]` (modelo solicitado, validado estrictamente contra lista permitida).

## 2. Requisitos de `GeminiProvider` (Verificados contra Docs Oficiales v1beta)

1. **Endpoint REST y Seguridad de Credenciales:**
   - Endpoint: `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent` (y `streamGenerateContent`).
   - Clave de API enviada **exclusivamente en la cabecera HTTP `x-goog-api-key`**.
   - **Cero apariciones de `?key=` en la URL**.
   - Claves tratadas estrictamente como `pydantic.SecretStr`, imposibilitando filtraciones accidentales en logs, trazas de excepción o serializaciones `repr()`.

2. **Formato de Payload y Turnos Reales:**
   - `system_instruction`: Separado en la raíz del payload (`{"parts": [{"text": ...}]}`).
   - `contents`: Lista de mensajes con roles alternados `user` y `model`. En entradas de visión, las imágenes se formatean como `inline_data` base64 con su respectivo MIME type.
   - Salida estructurada: Configura `generationConfig.responseMimeType = "application/json"` y `generationConfig.responseSchema = req.json_schema`.
   - **Reparación en un único reintento:** Si el modelo genera un JSON inválido o malformado, se realiza exactamente **un reintento de reparación** reenviando la salida del modelo con la instrucción de corregir la sintaxis JSON hacia el esquema requerido. Se erradicó el uso de regex frágiles del primer `{` al último `}`.

3. **Cadena de Modelos sin Hardcoding:**
   - La cadena de fallback se gobierna exclusivamente mediante la variable de entorno `GEMINI_MODELS` (por defecto `"gemini-3.8-flash,gemini-2.5-flash,gemini-2.0-flash"`).
   - Se validaron todos los identificadores en la documentación oficial de Google (sin incluir modelos descontinuados).
   - Se valida el parámetro `model` del usuario contra la lista de `GEMINI_MODELS` para impedir la inyección arbitraria de rutas o parámetros en la URL.

4. **Presupuesto de Tokens y Nivel de Pensamiento (`thinking`):**
   - Techo duro del modelo: **65.536 tokens** (`min(requested, 65536)`).
   - Presupuesto por propósito:
     - `chat`: 2.048 tokens (`LLM_MAX_OUTPUT_TOKENS_CHAT`)
     - `task`: 8.192 tokens (`LLM_MAX_OUTPUT_TOKENS_TASK`)
     - `codegen`: 32.768 tokens (`LLM_MAX_OUTPUT_TOKENS_CODEGEN`)
     - `vision`: 4.096 tokens (`LLM_MAX_OUTPUT_TOKENS_VISION`)
   - Documentación de razonamiento: El proceso de pensamiento interno consume parte de este presupuesto de salida. Se expone el control `thinking` (`low`, `medium`, `high`) mapeado al enum oficial de Gemini `thinkingConfig.thinkingLevel` (`LOW`, `MEDIUM`, `HIGH`).

5. **Reintentos Inteligentes y Cortacircuitos (`CircuitBreaker`):**
   - **Reintentos selectivos con backoff exponencial + jitter:** Aplica exclusivamente ante errores 429 (Rate Limit), 5xx (Server Error) o caídas de conexión/timeout (`httpx.TimeoutException`, `httpx.NetworkError`).
   - **Fast-fail sin reintento:** Ante errores 400 (Bad Request), 401 (Unauthorized) o 403 (Forbidden), falla inmediatamente lanzando `LlmBadResponse` o `LlmUnavailable`.
   - **Cortacircuitos simple:** Tras `LLM_CIRCUIT_BREAKER_FAILURES` fallos consecutivos (default 5), el circuito pasa a estado `OPEN` durante `LLM_CIRCUIT_BREAKER_RECOVERY_SECONDS` (30 s). En este estado, rechaza llamadas entrantes inmediatamente con `LlmUnavailable` protegiendo los recursos sin encadenar reintentos lentos. Tras 30 s entra en `HALF_OPEN` para probar la recuperación.

6. **Telemetría y Registro en `ai_usage`:**
   - Extrae el bloque `usageMetadata` de la respuesta de Gemini (`promptTokenCount`, `candidatesTokenCount`, `totalTokenCount`, y tokens de razonamiento si están presentes).
   - Registra de forma asíncrona y no bloqueante en MongoDB:
     ```json
     {
       "project_id": "...",
       "user_id": "...",
       "purpose": "chat|task|codegen|vision",
       "model": "gemini-3.8-flash",
       "tokens": { "prompt": 120, "candidates": 85, "total": 205, "thoughts": 30 },
       "latency_ms": 342.5,
       "ok": true,
       "created_at": "ISODate(...)"
     }
     ```
   - Colección optimizada con índices compuestos en MongoDB: `(project_id, created_at)` y `(user_id, created_at)`.

7. **Soporte BYOK (Bring Your Own Key):**
   - Encabezado HTTP `X-Gemini-Key`: Posee prioridad total sobre la clave del servidor (`GEMINI_API_KEY`).
   - Campos legacy en cuerpos JSON (`api_key`, `gemini_api_key`): Se aceptan temporalmente con aviso de deprecación en log (`logger.warning("Field 'api_key' in request body is deprecated; use header 'X-Gemini-Key'")`).
   - Todos los campos de clave en esquemas Pydantic tienen `Field(repr=False)` para impedir su visualización en logs o serializadores de depuración.

## 3. Migración de los 5 Clientes Existentes

| Módulo Original | Función Pública Conservada | Estado de Migración |
|---|---|---|
| `app/modules/ai/gemini_service.py` | `generate_uml_with_gemini(...)` | Migrado a `get_provider(purpose="task")`. Cero llamadas directas a HTTP; eliminación de hardcoding de modelos. Salida estructurada validada con esquema UML. Fallback a heurístico preservado. |
| `app/modules/ai/vision_service.py` | `generate_diagram_from_image(...)` | Migrado a `get_provider(purpose="vision")`. Imagen enviada como `inline_data` base64. Límite estricto de 8 MB. Cero uso de `?key=`. |
| `app/modules/codegen/gemini_generator.py` | `generate_backend_with_gemini(...)` y `generate_spring_boot_with_gemini(...)` | Migrado a `get_provider(purpose="codegen")`. Cero llamadas HTTP directas. Esquema JSON estructurado con archivos y resumen técnico. Fallback determinista intacto ante errores. |
| `app/modules/codegen/frontend_prompt_generator.py` | `generate_frontend_meta_prompt_with_gemini(...)` | Migrado a `get_provider(purpose="codegen")`. Enriquecimiento de meta-prompts mediante LLM y fallback determinista sin fallos. |
| `app/modules/ai_chat/service.py` | `_call_gemini_with_role(...)` | Migrado a `get_provider(purpose="chat")`. Atribución real de `project_id` y `user_id` para telemetría. Eliminadas listas locales de modelos. |

### Cambios adicionales en el ecosistema:
- **`requirements.txt`:** Se eliminó la dependencia obsoleta `google-generativeai>=0.8.0`.
- **`AI_CHAT_ENABLED`:** Convertido en un interruptor real. Cuando está en `false`, todos los endpoints de `/api/v1/ai-chat/*` responden inmediatamente con `503 Service Unavailable` (`code: SERVICE_UNAVAILABLE`) y mensaje claro.
- **`GET /api/v1/ai/health`:** Ahora reporta:
  ```json
  {
    "provider": "gemini",
    "models": ["gemini-3.8-flash", "gemini-2.5-flash", "gemini-2.0-flash"],
    "has_server_key": true,
    "ollama_available": false,
    "model": "tinyllama"
  }
  ```
  Sin ejecutar llamadas pagadas al proveedor Gemini.
- **Lifespan de FastAPI (`app/main.py`):** Instancia un único `httpx.AsyncClient` compartido durante el arranque y lo cierra limpiamente en el apagado.

## 4. Nuevas Variables de Entorno y Configuración

Documentadas en `.env.example`:

```env
# ── LLM Configuration (P2 unified client) ──────────────────────────────────
# Provider: "gemini" in production/staging; "fake" in automated tests and E2E
LLM_PROVIDER="gemini"

# Gemini server API key (handled as SecretStr; client may also pass X-Gemini-Key header)
GEMINI_API_KEY=""

# Ordered fallback model chain (verified current models only, no deprecated names)
GEMINI_MODELS="gemini-3.8-flash,gemini-2.5-flash,gemini-2.0-flash"

# Request timeouts and retries (backoff with jitter on 429/5xx/timeout; 400/401/403 never retried)
LLM_TIMEOUT_SECONDS=30.0
LLM_MAX_ATTEMPTS=3

# Circuit breaker (opens for 30s after 5 consecutive failures)
LLM_CIRCUIT_BREAKER_FAILURES=5
LLM_CIRCUIT_BREAKER_RECOVERY_SECONDS=30.0

# Token budgets per purpose (hard ceiling 65,536; reasoning/thinking consumes part of budget)
LLM_MAX_OUTPUT_TOKENS_CHAT=2048
LLM_MAX_OUTPUT_TOKENS_TASK=8192
LLM_MAX_OUTPUT_TOKENS_CODEGEN=32768
LLM_MAX_OUTPUT_TOKENS_VISION=4096

# Switch for AI chat service (when false, returns 503 Service Unavailable)
AI_CHAT_ENABLED=true
AI_CONTEXT_MAX_TOKENS=8000
```

## 5. Estrategia de Pruebas (68 Tests en Verde)

Todos los tests son 100% deterministas y se ejecutan sin llamadas de red:

1. **`test_gemini_provider.py` (11 tests con `httpx.MockTransport`):**
   - Transmisión obligatoria de la clave en cabecera `x-goog-api-key`.
   - **Ausencia absoluta de la clave en la URL** (`?key=` y `key=` no aparecen).
   - Estructura de payload: separación de `system_instruction`, roles `user` y `model`, configuración de `thinkingLevel` ("LOW", "MEDIUM", "HIGH").
   - Imágenes multimodales procesadas como `inline_data` base64.
   - Reintentos con backoff ante códigos 429 y 503.
   - Fallo inmediato (fast-fail sin reintentos) ante 400 Bad Request y 401/403 Forbidden.
   - Avance al modelo de respaldo en la cadena cuando el modelo principal falla.
   - Apertura y protección del cortacircuitos tras N fallos consecutivos.
   - Parseo completo de `usageMetadata` a `LlmUsage`.
   - Reintento de reparación único ante respuestas JSON malformadas.
   - Rechazo de modelos no autorizados para prevenir inyección de URLs.

2. **`test_fake_provider.py` (6 tests):**
   - Cumplimiento del protocolo `LlmProvider`.
   - Respuestas programables (`set_response`, `set_responses`, `set_error`).
   - Generación sintética predeterminada según esquema (UML, codegen, vision).
   - Generador asíncrono para streaming (`stream`).

3. **`test_llm_registry_and_health.py` (3 tests):**
   - Resolución dinámica del proveedor (`gemini` vs `fake`).
   - Contrato del endpoint `GET /api/v1/ai/health`.
   - Comportamiento de `AI_CHAT_ENABLED=False` retornando 503.

4. **`test_regression_and_security.py` (7 tests):**
   - Verificación estricta de que `?key=` no existe en ningún archivo de `app/`.
   - Verificación de que no existen llamadas HTTP a `generativelanguage.googleapis.com` fuera de `app/llm/`.
   - Regresión de `process_prompt` funcionando con `FakeLlmProvider` y fallback al heurístico cuando la IA falla.
   - Eliminación de claves API en `repr()` de Pydantic.
   - Ocultamiento de `SecretStr` en la configuración.
