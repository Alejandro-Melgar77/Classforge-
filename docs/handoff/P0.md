## 1. Resumen de Tareas Realizadas

### T1. Backend no arranca
- **Problema:** `app/modules/ai_chat/router.py:13` importaba `app.modules.auth.dependencies` (módulo inexistente), impidiendo la importación de `app.main`.
- **Solución:** Se corrigió la importación a `app.core.dependencies import get_current_user` sin crear shims innecesarios.
- **Verificación:** `python -c "from app.main import app; print(len(app.openapi()['paths']))"` imprime exactamente **54** paths (72 operaciones REST).

### T2. Frontend no compila — Corrección de errores
- **Problema A:** En `features/diagrams/ai-assistant/components/ai-drawer.component.ts` (~líneas 512–513), los bindings `[class.bg-blue-950/40]` y `[class.border-blue-500/30]` rompían el parser de plantillas de Angular debido a la barra inclinada (`/`).
  - **Solución:** Se reemplazó por directiva `[ngClass]="msg.author_type === 'ai' ? 'bg-blue-950/40 border-blue-500/30' : 'bg-slate-800 border-slate-700'"`.
- **Problema B:** En `features/ai-chat/components/ai-message-bubble/ai-message-bubble.component.ts:15`, el binding `[role]="message.ai_role as AiRoleId"` utilizaba la palabra reservada `as`, no permitida en bindings de Angular 17.
  - **Solución:** Se introdujo el getter tipado `get roleId(): AiRoleId | null` en el componente y se actualizó `[role]="roleId"`. Además, en `AiRoleAvatarComponent`, `@Input() role: AiRoleId | null = 'architect'` tolera valores nulos con fallback adecuado.
- **Verificación:**
  - `npx ng build --configuration development`: **0 errores** (Bundle generado con éxito).
  - `npx ng build --configuration production`: **0 errores** (Bundle optimizado con éxito).

### T3. Rutas del Chat con Binding de Inputs
- Se configuró `provideRouter(routes, withComponentInputBinding())` en `classforge-frontend/src/app/app.config.ts`, permitiendo que el componente `AiChatPanelComponent` reciba automáticamente el parámetro de ruta `:projectId` vía `@Input() projectId`.

### T4. Hotfix de Seguridad (password_hash)
- **Vulnerabilidad detectada:** `GET /auth/me`, `PUT /auth/profile` y `GET /users/{user_id}` devolvían el documento de usuario crudo extraído de MongoDB, exponiendo el campo sensible `password_hash`.
- **Solución:**
  - Se creó el esquema Pydantic `UserPublic` en `app.modules.auth.schemas` (y exportado en `app.modules.users.schemas`):
    - Atributos: `id`, `name`, `email`, `role`, `avatar_url`, `team_ids`, `is_active`.
    - Configuración con `extra = "ignore"`.
  - Se actualizaron los endpoints en `app/modules/auth/router.py` (`get_me`, `update_my_profile`) y en `app/modules/users/router.py` (`get_user`) para mapear explícitamente a `UserPublic`.
- **Test automatizado:** Se añadió `tests/test_auth/test_no_password_hash.py` comprobando que ninguna respuesta JSON de `auth/me`, `auth/profile`, `users/{user_id}` o `users/` contenga el substring `password_hash`.

### T5. Modelo por Defecto
- En backend `app/core/config.py`: `GEMINI_MODEL: str = "gemini-3.8-flash"`.
- En frontend `ai.service.ts`: default model actualizado a `'gemini-3.8-flash'`.
- En frontend `ai-drawer.component.ts`: default `selectedModel = 'gemini-3.8-flash'` y `gemini-3.8-flash` configurado como primera opción recomendada en `availableModels`. Soporte agregado a `getModelShortName`.

### T6. Tests Ejecutables y Tolerancia a Fallos de MongoDB
- **Conftest:** `tests/conftest.py` ahora respeta `MONGODB_URL` y `DATABASE_NAME` del entorno (`os.environ.setdefault`), sin sobreescribir configuraciones externas.
- **Tolerancia a fallos:** Se implementó verificación de conectividad con timeout rápido (1000 ms). Si MongoDB no está disponible localmente, el fixture `setup_db` emite un aviso claro y permite la ejecución del resto de tests sin abortar la suite con errores de setup.
- **Configuración de Pytest:** Se crearon `pyproject.toml` y `pytest.ini` configurando `pythonpath = .`, `asyncio_mode = auto` y `asyncio_default_fixture_loop_scope = function`.
- **Smoke test:** Se añadió `tests/test_smoke.py` que comprueba:
  1. Importación exitosa de `app.main`.
  2. Generación íntegra de OpenAPI (`app.openapi()`).
  3. Existencia de rutas críticas `/api/v1/ai-chat/projects/{project_id}/messages` y `/api/v1/auth/login`.

### T7. Pipeline de Integración Continua (GitHub Actions)
- Archivo creado: `.github/workflows/ci.yml`
- **Jobs:**
  - `backend`: Runner Ubuntu, Python 3.11, contenedor de servicio `mongo:6` con healthcheck, cache de `pip`, ejecución de `pytest -q`.
  - `frontend`: Runner Ubuntu, Node 20, cache de `npm`, `npm ci`, compilación `npx ng build --configuration production`.
  - `mobile`: Runner Ubuntu, `subosito/flutter-action@v2`, `flutter pub get`, `flutter analyze` (`continue-on-error: true`).
- Disparadores: `push` y `pull_request` a la rama `main`. No requiere secretos de Gemini.

## 2. Línea Base de Tests

### Línea Base Inicial (Antes de P0)
- **Ejecución:** Pytest fallaba inmediatamente con `ModuleNotFoundError: No module named 'app'` debido a la ausencia de path de módulos y error de importación en `app/modules/ai_chat/router.py`.
- **Tras solucionar importaciones pero con conftest original sin Mongo:**
  - **7 pasados:** Únicamente los tests de `test_codegen` (porque tenían un `conftest.py` local que sobreescribía `setup_db`).
  - **17 errores de setup:** Todos los demás tests fallaban antes de ejecutarse (`ERROR at setup of ...`) debido a:
    1. Incompatibilidad entre fixtures asíncronas con `autouse=True` y tests síncronos en pytest-asyncio.
    2. Colisión del fixture `anyio_backend` en modo estricto.
    3. Bloqueo de 30 segundos por test intentando conectar con MongoDB inexistente.

Comando: `pytest -q`
- **Total tests:** 26
- **Pasados:** 22

  - `tests/test_auth/test_auth_routes.py` (Validación de registro con campos faltantes -> 422)
