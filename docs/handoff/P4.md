# Handoff P4 — Chat de Equipo con IA: Modelo de Datos, API y Tiempo Real

**Fecha:** 1 de noviembre de 2026  
**Objetivo alcanzado:** Reemplazo integral del documento monolítico `ai_conversations` (con riesgo de desbordamiento de 16 MB en MongoDB) por una arquitectura escalable de mensajes individuales (`ai_messages`), estado de proyecto auditado (`ai_project_state`), memoria compartida ejecutiva (`ProjectDigest`), WebSocket de proyecto reactivo (`/api/v1/ws/projects/{project_id}`), ruteo determinista de 4 niveles para la intervención de roles de IA, y suite de pruebas unitarias y de integración completa en verde (128/128 tests pasando).

#### Índices creados en `app/core/database.py`:
- `(project_id, created_at desc)`: Consulta eficiente de historial ordenado.
- `(project_id, thread, owner_id, created_at desc)`: Consulta aislada de hilo personal (`/history/mine`).
- `(project_id, client_id)`: Índice único parcial (`partialFilterExpression: {"client_id": {"$type": "string"}}`), asegurando idempotencia estricta en reintentos de cliente.

### 2.3. Semántica de Hilos (Decisión de Diseño, CONTEXTO §8)
- **Chat:** Hilo personal del usuario con la IA (`thread: "personal"`, `owner_id: user_id`).
- **Historial:** Unión de todos los hilos personales de todos los integrantes + el hilo `project` (publicaciones globales de la IA: resultados de tareas, resúmenes, revisiones). Visible a **todos los miembros** del proyecto.
- **Sin mensajes privados:** `TODO(decisión)`: No hay canales ocultos entre usuarios. Si se solicita en el futuro, requerirá un nuevo esquema de aislamiento de claves y visibilidad.

## 3. Contrato de API REST (`/api/v1/ai-chat`)

Todas las rutas de proyecto requieren autenticación JWT y pertenencia al proyecto (`require_project_member`).

| Método | Ruta | Resumen y Comportamiento Clave | Código Éxito |
|---|---|---|---|
| `POST` | `/projects/{pid}/messages` | Envía mensaje. Guarda de inmediato el mensaje de usuario (idempotente por `client_id`). Genera IA en segundo plano. | `200 OK` |
| `POST` | `/projects/{pid}/messages/{mid}/retry` | Reintenta la generación para un mensaje de IA en `status: "error"`. | `200 OK` |
| `GET` | `/projects/{pid}/history` | Historial grupal del proyecto, paginado por cursor (`before`, `after`, `limit<=100`, `member`, `role`). | `200 OK` |
| `GET` | `/projects/{pid}/history/mine` | Mi hilo personal + publicaciones `project` de IA dirigidas al equipo. | `200 OK` |
| `GET` | `/projects/{pid}/state` | Lee estado compartido (`participative`, `roles`, `digest`). | `200 OK` |
| `PUT` | `/projects/{pid}/state` | Actualiza modo participativo o roles. **`autonomy: "apply"` restringido exclusivamente a Owner, Scrum Master o Admin** (`403` a Devs). | `200 OK` |
| `PUT` | `/projects/{pid}/roles` | Alias retrocompatible para activar/desactivar roles o cambiar su autonomía. | `200 OK` |
| `GET` | `/projects/{pid}/roles` | Lista de roles con status activo para el proyecto, skins UI y triggers. | `200 OK` |
| `POST` | `/projects/{pid}/messages/{mid}/proposals/{prop_id}/state` | Registra estado de propuesta (`applied` \| `dismissed`). Audita `by` y `at`. Difunde por WS. | `200 OK` |
| `GET` | `/projects/{pid}/tasks` | Lista tareas de IA del proyecto. | `200 OK` |
| `POST` | `/projects/{pid}/tasks` | Crea una nueva tarea asignada a un rol de IA. | `201 Created` |
| `PATCH`| `/projects/{pid}/tasks/{tid}` | Modifica campos de la tarea (título, descripción, rol, status). | `200 OK` |
| `DELETE`| `/projects/{pid}/tasks/{tid}` | Elimina/cancela una tarea. | `200 OK` |
| `PATCH`| `/projects/{pid}/tasks/{tid}/execute` | **Ejecución Asíncrona:** Encola la tarea en background, actualiza a `in_progress` y responde de inmediato. | **`202 Accepted`** |
| `GET` | `/projects/{pid}/ws-token` | Genera token de un solo uso (validez 5 min) para conectar al WebSocket de proyecto. | `200 OK` |

### 3.1. Ruteo de Roles (4 Niveles en Orden Estricto)
1. **`ai_role` explícito:** Si la petición incluye un rol válido (ej. `"architect"`), responde ese rol.
2. **`@mención` en el texto:** Si se menciona un rol (`@arquitecto`, `@qa`, `@techlead`, `@mentor`, `@dba`, `@seguridad`, `@analista`), se selecciona el rol mencionado. Si se menciona a compañeros (`@Nombre`), se registran en `mentions`.
3. **Modo Participativo (`participative.enabled == true`):** El router evalúa sin llamadas LLM extra (`route_ai_roles`) las palabras clave del mensaje contra los `triggers` de los roles habilitados con `autonomy != "off"`. Selecciona hasta 2 roles con mayor puntaje de coincidencia.
4. **Ninguno aplica:** Se guarda el mensaje del usuario; no se crea ninguna respuesta de IA (`ai_pending: []`).

### 3.2. Formato de Respuesta Inmediata (`POST .../messages`)
```json
{
  "message": {
    "id": "msg-123",
    "project_id": "proj-abc",
    "thread": "personal",
    "owner_id": "usr-456",
    "author_type": "user",
    "author_name": "Ana Dev",
    "content": "¿Cómo desacoplo la persistencia?",
    "status": "ok",
    "created_at": "2026-11-01T12:00:00Z"
  },
  "ai_pending": [
    {
      "role": "architect",
      "message_id": "msg-ai-789"
    }
  ]
}
```

## 4. Tiempo Real de Proyecto (`WebSocket`)

- **Ruta:** `/api/v1/ws/projects/{project_id}?token={ws_token}`
- **Sala:** `project:{project_id}` en `ConnectionManager`.
- **Autenticación:** Token de un solo uso consumido con `find_one_and_delete` en `db.ws_tokens`. Código `4001` si el token es inválido o expiró. Código `4003` si el usuario no pertenece al proyecto.
- **Límites:** Tamaño máximo 64 KB, ráfaga máxima 60 msg/s (código de cierre `4008`).

### Eventos Cliente $\rightarrow$ Servidor:
- `PING`: `{ "type": "PING" }` $\rightarrow$ Servidor responde `{ "type": "PONG" }`.
- `TYPING`: `{ "type": "TYPING", "is_typing": true|false }` $\rightarrow$ Difunde `AI_TYPING` al equipo.

### Eventos Servidor $\rightarrow$ Cliente:
- `PRESENCE`: `{ "type": "PRESENCE", "members": [...] }` (Integrantes conectados en vivo).
- `AI_TYPING`: `{ "type": "AI_TYPING", "role": str, "state": "start"|"stop", "user_name": str }`.
- `AI_MESSAGE_CREATED`: `{ "type": "AI_MESSAGE_CREATED", "message": {...} }`.
- `AI_MESSAGE_UPDATED`: `{ "type": "AI_MESSAGE_UPDATED", "message": {...} }`.
- `AI_STATE_CHANGED`: `{ "type": "AI_STATE_CHANGED", "state": {...} }`.
- `AI_TASK_UPDATED`: `{ "type": "AI_TASK_UPDATED", "task": {...} }`.
- `PONG`: `{ "type": "PONG" }`.

### Estrategia de Reconexión:
El WebSocket es un bus reactivo de eventos; **no es la fuente de verdad**. Al reconectar, el cliente pide:
```http
GET /api/v1/ai-chat/projects/{project_id}/history?after={ultimo_created_at_recibido}
```

## 5. Memoria Compartida (`ProjectDigest`) y Contexto Priorizado

1. **Job `summarize_digest`:**
   - Se ejecuta tras cada 20 mensajes nuevos o 30 minutos de actividad.
   - Genera un resumen ejecutivo $\le 1.500$ tokens con 4 secciones obligatorias:
     1. Objetivo del proyecto
     2. Decisiones tomadas
     3. Preguntas abiertas
     4. Peticiones clave por integrante (citando su nombre real)
   - Persistido en `ai_project_state.digest`.

2. **Prioridad de Recorte por Presupuesto (`AI_CONTEXT_BUDGET_TOKENS` = 8.000):**
   Si el prompt ensamblado excede el presupuesto disponible, se recorta en estricto orden de menor a mayor valor:
   $$\text{digest} > \text{diagrama} > \text{turnos propios} > \text{novedades}$$
   1. Se eliminan las **novedades de otros** ($\le 10$ líneas).
   2. Se reducen los **turnos propios** del hilo personal.
   3. Se compacta el resumen del **diagrama**.
   4. El **digest** se preserva íntegro como memoria de mayor prioridad.

3. **Adaptador `ProjectContextBuilder` corregido:**
   - Mapea `name` real (nunca `username`).
   - Resuelve los UUIDs de origen y destino de aristas a sus nombres de clase legibles.
   - Erradica la inyección de excepciones `str(e)`.

## 6. Script de Migración (`scripts/migrate_ai_conversations.py`)

- **Ejecución:**
  ```bash
  python scripts/migrate_ai_conversations.py [--dry-run] [--project-id <id>]
  ```
- **Idempotente:** Deduplica mensajes por `id` / `client_id`. Ejecuciones posteriores omiten registros ya existentes con cero duplicaciones.
- **Sin pérdida de datos:** Preserva la colección `ai_conversations` intacta (cero borrados).
- **Semántica:** Asigna `thread="personal"` para mensajes de usuario y sus respuestas directas, y `thread="project"` para anuncios globales. Inicializa `ai_project_state` si el proyecto carece de estado.
